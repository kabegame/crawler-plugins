# Patreon 创作者内容（WebView）

从 patreon.com 抓取创作者帖子的**图片**与**压缩包附件**。压缩包不进图库——它们由宿主解压后，
把里面的图片逐个入库。

## 使用前提：先登录 Patreon

Patreon 的附件几乎全是会员可见。本插件跑在真实浏览器窗口里，直接沿用你在该窗口内的登录态。
首次运行若未登录，窗口会弹出让你完成登录（以及可能出现的 Cloudflare 验证）。

## 为什么这个插件是 WebView 后端

`patreon.com` 全站在 Cloudflare 的**客户端指纹识别**之后。实测（2026-07-28）：HTML 页返回
`cf-mitigated: challenge`，`/api/*` 返回 403，连 `/api/current_user` 都拒。逐项排除过 Cookie
完整性、User-Agent、`Content-Type`、`sec-ch-ua` / `sec-fetch-*` 全套浏览器头、HTTP/2——
剩下唯一变量是 TLS/HTTP 客户端指纹。

普通 HTTP 客户端（V8 后端的 `fetch` 走宿主 reqwest，以及 curl）都过不去，**只有真实浏览器
引擎能过**。所以本插件用 WebView 后端：先由真实页面过挑战并拿到 `campaign id`，之后所有
接口请求都用页面自己的 `fetch`（同源、自动带 Cookie、真浏览器指纹）。

## 配置项

| 配置 | 说明 |
| --- | --- |
| 创作者或合集 | 直接粘链接即可，类型自动识别。详见下表。 |
| 爬取顺序 | 从新到旧（默认）/ 从旧到新。 |
| 最旧时间 / 最新时间 | 时间窗，两端都含当天。留空各有回落规则，见下。 |
| 只补充上次之后的新内容 | 记住上次抓到的最新时间，下次只补新增。 |
| 压缩包内提取规则 | glob 模式，决定包里哪些文件被提取入库。默认只要常见图片格式。 |
| 压缩包密码 | 部分创作者会加密附件并把密码写在帖子正文里。 |
| 同时下载帖子正文图片 | 关闭则只处理压缩包附件。 |

### 「创作者或合集」支持的输入形式

一个输入框适配全部类型，不需要额外选模式——URL 本身已经说明了它是什么。

| 输入 | 识别为 |
| --- | --- |
| `prprbecause31` | 创作者 |
| `https://www.patreon.com/c/prprbecause31` | 创作者 |
| `https://www.patreon.com/prprbecause31/posts` | 创作者 |
| `https://www.patreon.com/collection/1936000?view=expanded` | 合集（`?view=` 等展示参数会被忽略） |
| `collection:1936000` | 合集 |
| `1936000` | 合集（纯数字——Patreon 的创作者名不允许全是数字） |
| `https://www.patreon.com/posts/some-title-164455354` | 单帖 |
| `home` 或 `following` 或 `https://www.patreon.com/home` | 关注流（你订阅的全部创作者） |
| `id:12345678` | 直接给 campaign id，跳过一切解析 |

**合集**抓的是创作者自己整理的专题，按合集内的排列顺序（正序）返回，而不是按发布时间倒序。

**关注流**一次覆盖你订阅的所有创作者的最新帖，配合下面的增量模式最好用。

**单帖**直接从帖子页读取，不走列表接口，也不受时间窗影响。

### 爬取顺序与时间窗

**爬取顺序**决定 API 的排序方向，也决定时间窗的哪一端是「停止边」：

| 顺序 | 适合 | 遇到哪一端就停 |
| --- | --- | --- |
| 从新到旧（默认） | 日常补新 | 越过**最旧时间**即停 |
| 从旧到新 | 回溯补全历史 | 越过**最新时间**即停 |

另一端只能逐帖跳过（还没进入窗口），这是游标分页的固有代价。

**最旧时间**留空时的回落顺序：上次爬取记录 → 没有记录就一直翻到能扒到的最旧帖子。
**最新时间**留空表示一直到能爬取的最新帖子。

两个字段都是日期选择器，**两端都含当天**：最旧时间从当天 00:00 起算，最新时间算到当天
23:59:59。所以「最新时间 = 6/30」会包含 6/30 全天发的帖子，而不是只到 6/30 零点。

例外：**来自上次爬取记录的下界不含边界本身**（那一篇上次已经抓过，不该重下）。手填的下界含当天。

### 增量爬取：「只补充上次之后的新内容」

开启后（默认开），插件把本次处理过的**最新帖子时间**记进插件私有数据，下次作为最旧时间的默认值。

配合关注流最好用：目标填 `home`、顺序「从新到旧」，之后每次运行都只下新内容。

几个边界：

- **首次运行**没有记录，按全量抓取，结束时记下水位线。
- **合集不支持**。合集按 collection_order 排列而非时间序，方向和时间窗对它都不生效。
- **写回是无条件的**。爬取只会因两件事结束：撞到时间下界，或翻完最后一页——两者都意味着
  窗口内该抓的都抓了，不会有中间缺口。（早期版本有「起始页/结束页」，那时从新到旧一旦因页数
  上限提前停止就不能写回，否则会造成永久缺口；去掉分页参数后这个特例连同风险一起消失了。）
- 水位线按目标分别记录，创作者、关注流互不影响。

### 关于「压缩包内提取规则」

Patreon 的压缩包里经常混着 PSD 源文件、字体、说明文本。这些文件进不了图库，不过滤的话会刷出
一串失败记录。默认规则 `**/*.{png,jpg,jpeg,webp,gif,avif,bmp}` 只挑图片。

留空表示全部提取——除非你确认包里全是图片，否则不建议。

## 支持的压缩格式

`.zip`、`.7z`、`.tar`、`.tar.gz` / `.tgz`、`.tar.bz2` / `.tbz2`。

**`.rar` 不支持**：没有可用的纯 Rust 解码器，且官方 unrar 的许可证禁止用于重建 RAR 压缩算法。
遇到 rar 附件会给一条提示后跳过。

## 已知限制

- **不解 DRM**。Patreon 的视频普遍带 DRM，本插件不处理视频。
- **不绕订阅墙**。只能下到当前账号本就有权限的内容；无权查看的帖子会被跳过。
- `campaign id` 需要从创作者主页解析。Patreon 前端改版频繁，若解析失败，可以先在浏览器里找到
  campaign id，然后把「创作者」填成 `id:<campaign_id>` 绕开这一步。
