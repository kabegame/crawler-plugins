# Pixiv 爬蟲 - 外掛說明

本外掛用於從 Pixiv 爬取插畫，支援排行榜、個人收藏、畫師作品、關鍵詞搜尋與第三方 API 五種模式。

![home](./banners/home.jpg)

## 登入狀態

請先從 Kabegame 的暢遊畫面開啟 `pixiv.net`，此外掛就會自動以你的登入身分爬取。

### 如何取得使用者 ID（自己或畫師的）

透過暢遊或瀏覽器開啟 Pixiv 使用者主頁。

![user](./images/user.jpg)

網址中間或結尾的數字字串（圖中紅框）就是使用者 ID。

### 何時需要 Cookie

| 模式 | Cookie |
|------|--------|
| 排行榜（非 R18） | 可選 |
| 排行榜（R18） | 必填 |
| 個人收藏 | 必填 |
| 畫師作品（非 R18） | 可選 |
| 畫師作品（R18） | 必填 |
| 關鍵詞搜尋（非 R18） | 可選 |
| 關鍵詞搜尋（R18） | 必填 |
| 第三方 API（全年齡） | 不需要 |
| 第三方 API（R18／混合） | 必填 |

## 爬取類型

- **排行榜**：榜序＋內容＋年齡向；單一 `ranking_date`（留空為最新一期）
- **個人收藏**：下載你公開收藏的插畫
- **畫師作品**：下載指定畫師的公開作品
- **關鍵詞搜尋**：依關鍵詞搜尋並下載
- **第三方 API**：從第三方 API 取作品 id，再依 id 從 pixiv 下載詳情與原圖（目前支援 Lolicon API）

## 設定項

依選擇模式，表單會顯示不同設定項：

- **排行榜**：榜序、內容類型（有顯示時）、年齡向（R18 須 UID 與 Cookie）、`ranking_date`；分頁依 JSON **`next`**
- **收藏**：使用者 UID
- **畫師**：使用者 UID、畫師 UID
- **關鍵詞**：搜尋關鍵詞、搜尋模式（安全／R18／全部）、排序方式（按日期／按人氣）。**善用可精準爬取喜歡的內容**
- **第三方 API**：選擇 API 後顯示該 API 的參數，Lolicon 為年齡向、方向、標籤、畫師 UID、作品數、排除 AI、投稿起訖日期

## 最大作品數（`num_artworks`）

表單欄位為 **1～1000** 的整數，**排行榜、個人收藏、關鍵詞搜尋三種模式使用**（畫師作品依頁碼範圍，第三方 API 用各自的作品數）。計數單位是 **作品（一條插畫／條目）**，不是最終落盤的圖片張數；漫畫等多頁作品仍會依頁下載多張原圖，因此**檔案數可能大於** `num_artworks`。

腳本採用 **流式**：列表介面 **依頁請求**，每解析出一個作品 ID 就立即請求 `ajax/illust/{id}/pages` 並下載原圖；已達到 `num_artworks` 時 **立即停止**，不再預取後續列表頁，從而避免依目標總數反算頁數造成的空頁 **404**。

### 行為概要

1. **排行榜**  
   單一統計期內從 `p=1` 請求，下一頁取回應 **`next`**；`next` 為 false 時結束。未達 `num_artworks` 時 **warn**。

2. **收藏**  
   每頁 `limit=48`，拉一頁後**立刻下載**本頁各作品，直到達到 `num_artworks` 或書籤用盡。

3. **畫師**  
   列表仍依賴 **單次** `profile/all`（介面無分頁）；取得 `body.illusts` 的 key 後 **依序邊下邊數**，滿 `num_artworks` 即停。

4. **關鍵詞**  
   與排行榜類似：`p=1,2,…` 逐頁搜尋，頁內流式下載，滿額或結果不足一頁時結束。

## 設定執行範例（腳本實際流程）

以下說明任務啟動後的順序；URL 中 Cookie、模式等以表單為準。日期變數為 **`YYYYMMDD`**（無橫線）。

### 範例 A：排行榜（流式、`next` 翻頁）

| 設定項 | 範例值 |
|--------|--------|
| 爬取類型 | 排行榜 |
| 榜序 | 日榜（`daily`） |
| 內容類型 | 全部（`all`） |
| 年齡向 | 全年齡（`safe`） |
| 排行榜日期 | 留空或 `YYYYMMDD` |
| 最大作品數 | `120` |

**流程**  
從 `p=1` 請求 ranking JSON，以 **`next`** 為下一頁；滿 120 或 **`next` 為 false** 則停。

---

### 範例 B：個人收藏（分頁拉書籤，邊下邊停）

| 設定項 | 範例值 |
|--------|--------|
| 爬取類型 | 個人收藏 |
| 使用者 UID | 例如 `12345678` |
| 最大作品數 | `50` |

**流程**  
自 `offset=0` 起每頁 `limit=48` 請求書籤介面；對回傳的 `body.works[].id` **逐個**走 `pages` 下載，直到已處理 **50** 個作品或本頁不足 48 筆（無更多書籤）。

---

### 範例 C：畫師作品（全量清單一次，下載流式截斷）

| 設定項 | 範例值 |
|--------|--------|
| 爬取類型 | 畫師作品 |
| 登入使用者 UID（`x-user-id`） | 你的帳號 UID |
| 畫師 UID | 例如 `87654321` |
| 最大作品數 | `5` |

**流程**  
一次請求 `https://www.pixiv.net/ajax/user/87654321/profile/all?lang=zh`，再依 `body.illusts` 的 key 順序 **最多下載 5 個作品**（每個作品仍可能多圖）。

---

### 範例 D：關鍵詞搜尋（依搜尋頁流式）

| 設定項 | 範例值 |
|--------|--------|
| 爬取類型 | 關鍵詞搜尋 |
| 關鍵詞 | 例如 `初音ミク` |
| 搜尋模式 | 安全（`safe`） |
| 排序 | 按日期（`date_d`） |
| 最大作品數 | `25` |

**流程**  
`p=1,2,…` 請求 `ajax/search/artworks/...`；每頁對 `illustManga.data[].id` **邊下邊數**，滿 **25** 或單頁結果少於 60（通常無下一頁）則停。

---

以上四例對應四種 `source`。**共同點：以 `num_artworks` 為上限，可分頁列表均為流式。**

## 第三方 API 模式

第三方 API 只負責提供作品 id；詳情、評論、標籤與**全部分頁的原圖**仍從 pixiv 下載，與其它模式完全一致，所以仍需能連上 pixiv。請求第三方 API 時，外掛會暫時清空 pixiv 的 `Referer`、`Origin` 與 `Cookie`，你的 pixiv 登入狀態不會傳給第三方。

### Lolicon API

[Lolicon API](https://docs.api.lolicon.app/#/setu) 從它收錄的 pixiv 作品中**隨機**回傳，沒有分頁，一次任務只請求一次。

| 設定項 | 對應參數 | 說明 |
|--------|----------|------|
| 年齡向 `lolicon_r18` | `r18` | 全年齡／R18／混合。這是 Lolicon 庫內的分類，全年齡仍可能回傳 pixiv 標為 R-18 的作品，外掛會在本地依 `R-18`／`R-18G` 標籤再排除一次。R18 與混合需在暢遊登入 pixiv |
| 方向 `lolicon_orientation` | `aspectRatio` | 不限／橫圖（`gt1`）／直圖（`lt1`） |
| 標籤 `lolicon_tags` | `tag` | 每項之間為「且」，最多 3 項；一項內用 `\|` 分隔表示「或」，最多 20 個。同時匹配標籤、作者名與標題，如 `原神\|鸣潮` |
| 畫師 UID `lolicon_uids` | `uid` | 最多 20 個 |
| 作品數 `lolicon_count` | `num` | 1～20；條件太窄時實際回傳可能較少，會 warn 提示 |
| 排除 AI `lolicon_exclude_ai` | `excludeAI` | 預設開啟；只能排除 pixiv 明確標為 AI 的作品 |
| 投稿起訖日期 | `dateAfter`／`dateBefore` | 依 pixiv 投稿時間（日本時間）取整日，皆含當天 |

同一作品的不同頁會合併為一個作品並下載全部頁，所以落盤檔案數可能多於作品數。Lolicon 有呼叫頻率限制，被限流時外掛會等 15 秒重試，最多 3 次。

## 注意事項

- 排行榜若最終數量不足 `num_artworks`，會 **warn** 提示。
- 若遇 403，可重新取得 cookie。若僅偶發，可能是被限流，多執行幾次任務，或改在暢遊頁面手動下載。
- Cookie 過期後需重新取得
- 關鍵詞支援進階搜尋語法，如 `(Lucy OR 邊緣行者) AND 5000users`
- **按人氣排序**需 Pixiv Premium 帳戶，非 Premium 請使用「按日期」
- 請合理設定最大作品數，避免對 Pixiv 造成過大負擔
