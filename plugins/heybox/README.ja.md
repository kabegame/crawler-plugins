# 小黑盒（Heybox）の画像をアルバムに保存する方法

このガイドでは、小黑盒で見つけたお気に入りの画像を Kabegame に保存するときの全体的な流れを説明します。手順に沿って進めれば、処理の流れを把握できます。スクリーンショットは Kabegame Windows v3.4.3 のものです。

---

ソースに「小黑盒」を選択します。

![小黑盒をソースに選択](./src-xhh.png)

## 1. 投稿の探し方を選ぶ

小黑盒には 2 つの取得方法があります。目的に合う方を選んでください。

### 1. キーワードで検索する

特定の種類の画像を探したいときに使います。

1. **クロールモード**で「キーワード検索」を選択します。

![キーワード検索モード](./mode-keyword.png)

2. **検索キーワード**に、壁紙、ゲーム名、cosplay など探したい言葉を入力します。

3. 必要に応じて**開始ページ／終了ページ／1ページあたり件数**を設定します。数値を大きくすると一度に多くの投稿を確認できますが、その分時間もかかります。経験上、5 件前後がアクセス制限のかかりやすくなる目安です。

![キーワード検索設定](./params.jpg)

4. 取得を開始すると、ページごとに検索し、開ける投稿を 1 件ずつ処理します。

![ダウンロード中](./downloading.png)
![取得した画像](./banners/images.jpg)
![画像プレビュー](./banners/image-preview.jpg)

### 2. 1 件の投稿だけを取得する

投稿リンクがすでに分かっているときに使います。

1. **クロールモード**で「単一投稿 URL」を選択します。
2. 小黑盒の**投稿を共有**ボタンからコピーしたリンクを、**投稿共有 URL**に貼り付けます。必ず共有ボタンでコピーしたリンクを使用してください。ブラウザーのアドレスを直接コピーしたものは利用できません。下の画像を参照してください。

![投稿を共有ボタン](./share-btn.png)

貼り付け：

![URL を貼り付け](./url-paste.png)

3. この投稿だけが処理され、検索ページは巡回しません。

![単一投稿の画像](./url-images.png)
![単一投稿の画像プレビュー](./url-image-preview.png)

**個人的なおすすめ**  
おすすめは 2 番目の方法です。先に小黑盒で気に入った投稿を見つけ、共有リンクをコピーしてから画像を取得します。通常はこちらの方が**ブロックされにくく**、**狙った画像を正確に取得でき**、無関係な投稿も混ざりません。

---

## 2. 投稿が見つかった後、画像が保存されるまで

検索で見つけた投稿でも、URL を指定した投稿でも、**投稿ごとに**次の処理を行います。

1. **投稿本文の構造を取得する**  
   本文ではテキストと画像がブロック単位で並んでいるため、プラグインが順番に確認します。

2. **画像ブロックだけを認識する**  
   画像を表すブロックごとに、まず小さなプレビューを取得し、画像の順番と枚数を確認します。

3. **小黑盒に大きな画像の URL を問い合わせる**  
   各プレビューに対応する大きな画像の URL をもう一度取得し、URL が得られた画像だけをアルバムへ保存します。

4. **複数の画像は別々に保存する**  
   同じ投稿に複数の画像がある場合は、タイトルの後ろに番号を付けるなど、名前を区別して保存します。

5. **コメント欄（任意）**  
   **コメント画像をダウンロード**を有効にすると、コメント内の画像も階層ごとに取得します。投稿によっては、コメント欄に多くの画像があることもあります。無効にすると本文の画像だけを取得します。

---

## 3. ときどき発生する状況

- 本文に**画像がまったくない**投稿はスキップされます。
- 小黑盒から認証を求められたり、一時的にアクセスを止められたりする場合があります。ネットワークを切り替えるか、しばらく待ってから再試行すると改善することがあります。
- 投稿間や画像間で**少し待機**するため、完了までしばらくお待ちください。

## 4. 設定一覧

| 設定 | 表示条件 | 役割 | 既定値 |
| --- | --- | --- | --- |
| クロールモード | 常時 | キーワード検索／単一投稿 URL | キーワード検索 |
| 投稿共有 URL | 単一投稿モード | 共有リンクを貼り付ける | 空欄 |
| 検索キーワード | キーワード検索 | 検索する内容 | 美图 |
| 自動コメント | 常時 | 取得した投稿にいいねを付け、コメントを 1 件投稿 | オフ |
| コメント本文 | 自動コメント有効時 | 投稿するコメント文 | 我用 kabegame 把美图拿走喽，谢谢！ |
| 開始ページ（1 から） | キーワード検索 | 結果の取得を始めるページ | 1 |
| 終了ページ（含む） | キーワード検索 | 取得する最後のページ | 1 |
| 1ページあたり件数 | キーワード検索 | 1 ページで取得する投稿数 | 5 |
| コメント画像をダウンロード | 常時 | 本文＋コメント画像／本文のみ | オン |

## 5. 重要な注意事項

**Cookie（上級者向け）**  
**Cookie** は、ログイン状態の維持などに使われる、Web サイトがブラウザーへ保存する小さな情報です。**取得開始 → 詳細設定 → HTTP ヘッダー**で「ヘッダーを追加」を選び、名前に `Cookie`、値にブラウザーからコピーした文字列を入力します。**設定 → プラグインの既定値 → クローラープラグインの既定設定**で、このプラグインの既定リクエストヘッダーとして保存しておけば、タスクごとに入力する必要はありません。**アカウント停止やログイン制限などの危険があるため、自己責任で使用してください。**

**Cookie を付ける利点**  
小黑盒のバックエンドは、「未ログインのままスクリプトが投稿詳細をまとめて取得しているように見える」アクセスを厳しく判定します。公式 API を使っていても、**Cookie がない**場合は**投稿本文や入れ子のコメント（tree）**を取得する段階で CAPTCHA を要求されやすく、投稿を 1 件も完全に開けないことがあります。**小黑盒にログイン済みの Cookie**を付けると、リクエストは**ログインユーザー**として処理されます。テストでは、匿名アクセスよりも複数の投稿詳細を連続して安定的に取得できました。

そのため、キーワード検索で多くのページを巡回する場合や、開始直後から認証を繰り返し要求される場合は、詳細設定で Cookie を指定してみてください。共有リンクを 1～2 件だけ時々取得するなら Cookie なしでも動くことがありますが、通常は指定した方が安定します。

**アクセス制限やタスクエラーが発生した場合**

![認証画面](./captcha.png)

**タスク**で該当する項目を開き、**ログ**を選択すると、**タスクログ**画面で詳細を確認できます。諦めず、次のいずれか、または複数を試してください：**プロキシノードを変更する**（多くの場合はこれだけで解決します）、**時間を空けて再試行する**（半日または 1 日待つ、もしくは別のネットワークを使う）、**Cookie を付ける**（上記の Cookie の項を参照。一般にログイン状態の方が匿名アクセスより安定します）。
