# Kemono 爬蟲

本外掛從 `kemono.cr` 取得作者貼文及其附件。內容可能包含成人內容，請遵守所在地法律、網站規則與內容授權要求。

## 五種爬取模式

### 連結

填寫以下任一形式的完整連結：

- 作者全部貼文：`https://kemono.cr/<service>/user/<uid>`
- 單篇貼文：`https://kemono.cr/<service>/user/<uid>/post/<pid>`

舊網域 `kemono.su`／`kemono.party` 的連結也能辨識，但請求一律使用目前網域 `kemono.cr`。指定單篇貼文時，會直接呼叫單篇貼文 API，不會翻閱該作者的完整列表，也不受頁數範圍影響。

### 作者

分別選擇「作者服務」並填寫「作者 ID」。支援的服務為 `patreon`、`fanbox`、`gumroad`、`subscribestar`、`dlsite`、`discord`、`fantia`、`boosty`、`afdian`。

上游 `kemono-scraper` 也支援姊妹站 Coomer（`onlyfans`、`fansly`），但那是成人訂閱內容而非動漫圖片，因此本外掛不予移植；收藏清單中若混有這類項目，會被自動跳過。

### 收藏的作者

讀取該帳號在 Kemono 收藏的作者，再逐一取得每位作者的貼文。**同時受兩個頁數範圍限制**：先用「收藏作者頁數範圍」決定處理哪些收藏作者，再用「作者頁數範圍」決定每位作者要取得哪幾頁貼文。

### 收藏的貼文

讀取該帳號在 Kemono 收藏的貼文，依「頁數範圍」截取後逐一下載。

### 標籤

填寫一個網站標籤（如 `nsfw`、`wip`、`comic`、`nude`），依「頁數範圍」爬取全站帶有該標籤的貼文。標籤**區分大小寫**，需與網站上的寫法一致；全部標籤可在 `kemono.cr/posts/tags` 查看。本模式不需要登入。

## 頁數範圍

所有適用的模式都以「頁」為單位限制爬取量，**每頁 50 筆**，頁碼從 1 開始，結束頁填 `0` 表示一直到最後一頁。

| 模式 | 生效的頁數範圍 |
|---|---|
| 作者／作者連結 | 作者頁數範圍（貼文列表） |
| 收藏的作者 | 收藏作者頁數範圍 **＋** 作者頁數範圍（疊加） |
| 收藏的貼文 | 頁數範圍 |
| 標籤 | 頁數範圍 |
| 單篇貼文連結 | 不適用，直接取得該貼文 |

外掛以**串流方式**運作：每翻一頁，就會先下載完該頁貼文的附件，再翻到下一頁，不會事先累積完整列表。因此即使中途取消任務，已下載的部分仍會保留。

收藏清單由 API 一次回傳，其「頁」是外掛在本機依每頁 50 筆切分的，語意與貼文列表的頁面一致。

## 收藏模式與暢遊登入

收藏 API 需要登入 Cookie。外掛不會讀取 Cookie 檔案，也不會探測瀏覽器 Cookie；請先在 Kabegame 的「暢遊（Surf）」中開啟並登入 `kemono.cr`，再執行收藏模式。

如果暢遊中沒有該網站的 Cookie，任務會直接提示登入。如果收藏或後續列表請求回傳 `401`／`403`，代表登入狀態已失效，請回到暢遊重新登入。

連結、作者、標籤三種模式不需要登入。

## 圖片來源：縮圖與原圖

**預設下載縮圖，這是刻意的選擇。**

Kemono 將原圖放在 `n1`～`n5`、`c1`～`c3` 等獨立檔案節點上。實測（2026-07）這些節點在許多網路環境中，無論是否使用代理，**在 TCP 層就無法連線**；而縮圖主機 `img.kemono.cr` 可以正常存取。因此：

- **縮圖（預設）：**長邊上限 800px，單張約 30～40KB，來自 `img.kemono.cr`，能穩定下載。
- **原圖：**來自上述檔案節點。如果你的網路確實能連線，便可取得完整畫質；若無法連線則會全部失敗。

800px 對壁紙用途來說是明顯降級，但在原圖節點無法存取的前提下，這是唯一能取得圖片的途徑。如果網路環境改變，可以在設定中切回原圖試試。

**縮圖模式會自動跳過壓縮檔、影片等附件**——這類檔案沒有縮圖，請求一律回傳 404；若不跳過，整篇貼文都會出現大量失敗。

## 附件說明

貼文附件不一定是圖片，也可能是影片、音訊、壓縮檔或其他檔案。原圖模式下，外掛會把所有附件交給 Kabegame 下載；能否預覽取決於 Kabegame 和目前平台對該媒體類型的支援。

「包含 Banner／主檔案」對應原下載器的 `--banner` 行為：將貼文的 `file` 欄位加入附件。即使關閉此選項，非圖片主檔案仍會保留；在縮圖模式下，仍會因為沒有縮圖而被跳過。

同一篇貼文的所有附件共用一份精簡貼文 metadata。多個附件會在貼文標題後加上 `(1)`、`(2)` 等編號；與原下載器一致，圖片和非圖片附件會分別編號，因此不同類型的檔案可能出現相同編號。
